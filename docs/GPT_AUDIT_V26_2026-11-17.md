## Follow-up findings

### P2 — Output-path guard is useful but not atomic

lib/output-path.ts rejects a filesystem root, the repository root and its ancestors, and existing symlink components. main.ts calls it before mkdirSync and again after directory creation. The four new tests cover an allowed dedicated directory, repository root/ancestor rejection, an existing symlink component, and filesystem-root rejection.

Residual issue: after the final safeOutputPath check, main.ts still performs path-based rmSync calls. A process with write access to a relevant parent can replace a checked component between validation and deletion. This is a local TOCTOU race, not evidence of a remote exploit. Treat the guard as protection against static unsafe paths, not as an atomic symlink-race defence. Document the trusted-parent assumption or adopt a design whose guarantees match the threat model.

### P1 — Farm actions and rewards remain unsupported by snapshot evidence

actionFor() and weeklyFor() still prescribe protocol actions such as supplying USDC, using a main pool, bridging, staking, borrowing, minting, voting, spending or rebalancing based on broad category labels. claimFor() tells nearly every family to open its own points/rewards page. The snapshot schema has no per-protocol supported-asset, product-capability, route, rewards-programme or rewards-URL evidence. “Verify on the official app” does not make the preceding transaction instruction evidence-backed.

Until capability evidence is attached to the exact protocol, default to a non-transactional verify-first instruction. Do not emit rewards-page claims without a verified programme/page. Keep the $50/$100/$200 TVL-derived capital bands explicitly illustrative, not protocol minimums or safe allocations.

### P1 — Growth/maturity sensitivity is still untested

The model retains the 7-day growth weights and the 0.70–1.00 listing-age multiplier over 1,460 days. The existing tests pin constants; they do not quantify rank movement with growth neutralized, maturity neutralized, or both. Add a deterministic sensitivity report with median, p90 and maximum rank movement plus top-N membership changes. Keep the submitted model and board unchanged unless Rama explicitly authorizes a new model version. The sealed snapshot is not in the public repository, so real-board sensitivity remains blocked until the permitted kit input is available; synthetic sensitivity tests can proceed independently.

### P2 — Yield Aggregator is still misclassified

familyFor() checks the DEX branch for c.includes('yield') before the curator/aggregator branch. “Yield Aggregator” therefore resolves to dex. The fixture exists, but the family test only rejects the old generic deposit fallback; it does not assert the expected family or exact family action. familyFor() also lowercases without trimming, unlike normCategory(). Normalize once and assert expected family/action results for overlapping, whitespace and case variants.

### P1 — Snapshot validation still accepts malformed values

parseSnapshot() checks the calendar shape of a string listed_at but does not compare it with as_of. A valid future date is accepted and later becomes a null age. A non-string listed_at is silently converted to null. Negative finite mcap_usd is retained instead of rejected. Chain deduplication uses raw Set values, so “Ethereum”, “ethereum” and “ Ethereum ” can all count separately and inflate breadth. Add parser-level negative tests and canonicalize comparison keys while retaining a display label. Category normalization is also inconsistent: CEX exclusion uses exact string comparisons, while family classification lowercases but does not trim.

### P1 — Board gate does not bind row order to rank or enforce the tie-break

buildBoard() sorts by implied value descending and slug ascending, so its normal output has a deterministic tie-break. boardIssue(), however, sorts the rank values before checking contiguity; it does not require board[i].rank === i + 1 and does not verify slug order when adjacent implied values tie. The existing tests check the builder's output, not a deliberately reordered board with swapped rank fields. Add negative fixtures proving the gate rejects both cases.

### P2 — Current output and CI evidence remain incomplete

The model suite has four sealed-snapshot tests configured to skip when the snapshot is absent. The sealed snapshot and generated board are not in the public repository. scripts/rebuild.sh compares board.json, data.js and dossier.json across two fresh runs, but no rebuild was independently executed in this review. The combined status check list for main HEAD is empty and the available PR-triggered workflow-run query returned no runs. Do not treat the implementation author's historical test/rebuild report as current exact-head CI evidence.
