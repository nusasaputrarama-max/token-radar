## Findings

### Confirmed improvements

- `parseSnapshot()` rejects non-string non-null `listed_at` values and dates later than `as_of`. Negative finite `mcap_usd` values are normalized to `null`, so they cannot be used as positive comparables or live prices. This is a documented deviation from hard rejection: the PR/report says the sealed snapshot contains `autofinance` with `mcap_usd: -1` and token metadata. The sealed input was not available to this reviewer, so that specific record-level rationale remains implementer-reported, not independently checked.
- `isCexCategory()` applies trim + case-fold normalization. Source review found no remaining raw `category === 'CEX'` / `!== 'CEX'` checks; rankability, live lists, comparable pools, and excluded-category buckets use normalized predicates.
- `boardIssue()` now requires `board[i].rank === i + 1` and checks ascending slug order for equal implied values. New negative fixtures exercise swapped rank fields and reversed tied rows.
- `docs/output-path-threat-model.md` explicitly states the static-path guarantee, trusted-parent/group assumptions, and the remaining check-then-use TOCTOU window. `lib/output-path.ts` only adds a pointer to this document; the race itself is not eliminated.

### P2 — Board gate still delegates watchlist eligibility to the builder

`buildBoard()` rejects watchlist members that are not rankable or are below `floor_usd`. `boardIssue()`, however, only checks that each watchlist member exists and is pre-token. Its expected set begins with every watchlist slug, and the gate does not independently require `isRankable(p)` or `p.tvl_usd >= snapshot.floor_usd`. A crafted board/snapshot pair can therefore pass `boardIssue()` with a CEX/versioned or below-floor watchlist member if the remaining row invariants are satisfied. `main.ts` calls `buildBoard()` before `boardIssue()`, so the normal generator path currently rejects those inputs; the exported gate is nevertheless not a self-contained proof of the full watchlist contract.

**Required:** add rankability and floor checks inside `boardIssue()` and negative direct-gate fixtures for CEX, versioned, and below-floor watchlist entries.

### P1/P2 — v2.7 farm-plan wording remains unresolved

The source still contains the chain-family instruction to “use it and keep a small balance active” in both `actionFor()` and `weeklyFor()` (`lib/model.ts`, around lines 664 and 720). The generated step-2 cost still states `$50`, `$100`, or `$200` of capital according to TVL bands, and the hold step repeats that amount as capital remaining in the position. These amounts are not labelled as illustrative assumptions or non-prescriptive examples.

The current negative-action test does not catch the small-balance wording or the capital bands; its forbidden patterns focus on transaction verbs and legacy deposit/rewards wording. The family fixtures assert a verify-first prefix but do not assert that the chain family avoids a balance recommendation. The prior v2.7 finding therefore remains OPEN.

**Required:** remove the balance instruction or make it verification-only; label capital bands explicitly as illustrative and non-prescriptive or remove them; test all six rendered steps and cost fields.

### P2 — Output-path security remains partial, but the limitation is now explicit

Keep the status PARTIAL/BLOCKED unless the threat model is narrowed operationally or cleanup is redesigned around descriptor-relative operations/private run-owned directories.
