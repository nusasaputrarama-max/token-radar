## Source-level checks

### Improvements confirmed in source

- `familyFor()` now applies `normCategory()` and checks curator/aggregator before the broad DEX/yield rule. Tests assert the expected family for Yield Aggregator, case variants and whitespace variants.
- `dedupChains()` trims and case-folds chain labels; it is applied during parsing and again in `impliedValue()`. Tests cover cosmetic variants and breadth invariance.
- `sensitivityAnalysis()` rebuilds growth-neutral, maturity-neutral and both-neutral boards from copied model constants. It reports moved rows, median/p90/max rank deltas and top-10/25/50 membership changes without mutating `MODEL`.
- `buildBoard()` sorts by implied value descending and slug ascending. `boardIssue()` constructs the expected eligible set (watchlist plus rankable pre-token rows below the floor), and rejects missing, extra and duplicate slugs.
- The output-path guard rejects unsafe path shapes, checks ownership and permissions, and revalidates each cleanup target immediately before `rmSync()`.
- Static dashboard review found no `fetch`, XHR, WebSocket, EventSource, `sendBeacon`, dynamic import, HTTP(S) URL, or protocol-relative URL in `dashboard/app.js`. `dashboard/index.html` references only local `app.css`, `../data.js` and `app.js`; the stylesheet contains no CSS `url()`. This is a static check, not a browser runtime test.

### Open finding — farm plan is not fully non-transactional

The entry action is verify-first for the listed families and `claimFor()` asks the user to verify whether a programme exists rather than asserting that one does. However:

- The `chain` entry branch still says to use an app and keep a small balance active after verification; the `chain` weekly branch repeats the instruction to keep a small balance active. The snapshot does not establish a required balance or user-specific suitability.
- Step 2's cost field still emits `$50`, `$100` or `$200` of capital from TVL bands. It is not clearly labelled in the generated plan as an illustrative modelling assumption, not a protocol minimum or user-specific capital recommendation.
- The negative test's forbidden patterns do not catch the small-balance wording or the capital-cost field; the per-family fixture primarily asserts the entry text and rewards check.

**Disposition: PARTIAL.** Remove the balance instruction or make the whole step verification-only. Label capital bands explicitly as illustrative and non-prescriptive, or remove them. Extend tests to inspect all six rendered steps and cost fields.

### Open finding — snapshot validation still accepts invalid values

In `parseSnapshot()`:

- A future `listed_at` date is calendar-valid and is not rejected against `as_of`. `ageDays()` returns `null`, after which the model substitutes the unknown-age default; invalid future data is therefore silently treated as missing.
- A non-string, non-null `listed_at` is silently converted to `null`.
- A finite negative `mcap_usd` is retained. It is neither rejected nor normalized to missing; it later falls into the unpriced state.

The tests show that `ageDays()` returns null for a future date, but the parser tests do not prove that `parseSnapshot()` rejects a future date, a non-string date, or negative market cap.

**Disposition: OPEN (P1).** Accept only null/absent or a valid string date not later than `as_of`; reject negative finite market caps. Add parser-level negative fixtures for each case.

### Open finding — board gate does not bind rank to row index or enforce tie-break

`boardIssue()` sorts the rank values and checks that they form 1..N, then checks non-increasing implied value. It does not require `board[i].rank === i + 1`, and it does not enforce ascending slug when adjacent implied values are equal.

`buildBoard()` currently emits the right order, and a positive fixture verifies its slug tie-break. That does not make the independent gate reject a tampered/reordered board. The board gate test has no negative fixture for swapped rank values or equal-value rows in reverse slug order.

**Disposition: OPEN (P1).** Bind each row's rank to its array index and enforce the documented slug tie-break in the gate; add negative fixtures.

### Open finding — CEX exclusion still uses raw category equality

`normCategory()` exists, but `isRankable()` and the live-comparable filter in `buildBoard()` still use `p.category !== 'CEX'`. `buildRadar()` also filters the live pool with the raw exact string. A value such as `cex` or ` CEX ` can bypass the exclusion and enter ranking or comparable calculations. No evidence establishes that the sealed snapshot contains such a variant, so this is an input-hardening defect, not a claimed current-board mismatch.

**Disposition: OPEN (P2).** Use one normalized category predicate for CEX exclusion and add case/whitespace fixtures.

### Output-path guard — partial, not fully race-safe

The code now rejects static unsafe paths and revalidates each cleanup target. The tests simulate a symlink swap before the final per-entry check; they do not exercise a concurrent swap after that check but before `rmSync()`. The source comment correctly acknowledges that path-based checks cannot atomically close that interval.

Commit `8d071f7` also changed the output-directory check to accept group-writable mode (for example 0770), based on the assumption that the current user's group is trusted. The code cannot establish whether that group contains untrusted users.

**Disposition: PARTIAL.** Keep the residual TOCTOU and group-trust assumption explicit. Use an exclusively controlled/private parent for runs; do not claim race elimination. A stronger descriptor-relative/atomic cleanup design would be needed for a stronger guarantee.

### Growth/maturity sensitivity — diagnostic delivered; calibration not closed

The report records growth-neutral movement of 182/226 rows (median 2, p90 8, max 41), maturity-neutral movement of 203/226 (median 3, p90 10, max 20), and both-neutral movement of 187/226 (median 3, p90 13, max 39); top 10 is reported stable in all variants.

The diagnostic code and synthetic tests are present. The real-snapshot figures remain implementer-reported: the sealed snapshot is not in the public repository and could not be obtained in this run. The model constants remain unchanged. The snapshot only contains 7-day change, so longer trend sensitivity cannot be inferred from it.

**Disposition: DIAGNOSTIC IMPLEMENTED; CALIBRATION BLOCKED pending an explicit owner decision.** Do not change model constants or submitted board identity as part of this audit.
